# 咕叽咕叽桌宠开发计划

状态：M1、M2 已实现，M4 进行中

当前版本：`0.8.1`

目标平台：Windows 10/11 x64

产品定位：DSH 的轻量桌面伴侣，只显示一只桌面悬浮宠物，不在 DSH 窗口内重复显示。

## 1. 产品目标

下一阶段不做“功能越多越好”的桌宠，而是把它做成一个克制、耐用、低打扰的工作伙伴：

- 拖动和甩出要像真实物体，优先参考 QQ 宠物的抓取、抛出、落地和碰撞手感。
- 状态只反映 DSH 的真实任务，不在空闲时伪造“工作中”。
- 鼠标正常工作时不被抢夺，不监听全局鼠标轨迹。
- 空闲时物理计算完全休眠，避免 60 FPS 常驻消耗。
- 所有显示器组合下，宠物和状态浮窗都不能被屏幕分界线切成两半。
- 先稳定 Python 版本，再用原生壳把安装包和内存降下来。

## 2. 当前基线

### 已实现

- 桌面单实例宠物；DSH 窗口内不注册第二只宠物。
- 单击随机播放歪头、伸头、展翅或挥翅；动作首尾为站立。
- 双击打开或收起 DSH 窗口，并恢复被折叠的任务浮窗。
- 右键设置或隐藏宠物。
- 工作浮窗显示项目名、当前活动，长文字横向循环滚动。
- 空闲不显示“空闲”字样。
- 宠物大小、透明度可调且持久化。
- 可拖到同一显示器内任意位置，并会避让工作区边缘。
- 任务失败、等待审批、运行中有不同状态。
- DSH 回合正常完成后连续轻跳两次，失败、中断和超限不触发。
- 已处理双屏 DPI 感知、透明置顶窗口和屏幕工作区。

### 当前限制

- 飞行中尚未加入整图倾斜、抓取滞后的次级动效和“甩出力度”设置。
- 当前帧使用最近邻缩放，高速飞行时还没有运动模糊；后续只在确有必要时增加。
- Python/Tk/Pillow 运行时占用较大。
- `0.6.0` 的 npm 包约 `23.33 MB`，其中桌面 EXE 约 `22.45 MB`。
- `assets` 总共约 `2.98 MB`，包含开发检查图和大量重复动作帧。
- 当前机器实测桌宠子进程私有内存约 `64.7 MB`，工作集约 `96.2 MB`；这是优化重点，不应继续增加常驻资源。

## 4. 设计原则

1. **任务优先**：宠物用于提示状态，不遮挡用户当前工作。
2. **短时动效**：甩出、落地、撞墙是短事件；空闲不持续跑物理。
3. **默认安静**：不播声音，不自动漫游，不抢占焦点，不读写用户文件。
4. **可预期**：松手轻放就自然落下；用力甩出才飞出；不会无限微弹。
5. **整窗不切割**：窗口可以透明留白，但可见身体不能在双屏分界处只显示一半。
6. **先 Python 验证，再原生替换**：交互定稿前不做高风险重写。

## 5. 核心技术方案

### 5.1 分层

建议新增纯逻辑模块 `desktop/pet_physics.py`，不依赖 tkinter：

```text
Tk pointer/window events
        |
        v
PetPhysicsModel
  - drag samples
  - release velocity
  - position / velocity
  - gravity / friction / restitution
  - monitor bounds / seam handoff
        |
        v
PetWindow adapter
  - move Tk window
  - pre-rendered sprite transform
  - bubble follow / hide / restore
```

边界要求：

- `pet_physics.py` 只处理数值和状态，可用标准库 `unittest` 测试。
- Tk 层只负责采样、计时、窗口移动和渲染，避免把物理规则散落在事件回调里。
- 物理测试不启动 GUI，不依赖 Pillow。
- 后续原生实现可以直接复用同一组参数和验收用例。

### 5.2 状态机

| 状态 | 进入条件 | 行为 |
| --- | --- | --- |
| `IDLE` | 没有拖动或飞行 | 只保留现有待机/任务动画，不跑物理计时器 |
| `PRESSED` | 左键按下 | 记录抓取偏移、初始窗口位置、时间；不立即判定拖动 |
| `DRAGGING` | 位移超过约 5 px | 1:1 跟随指针；记录最近 150ms 位置 |
| `AIRBORNE` | 松手且估速达到甩出阈值 | 重力、空气阻力、墙壁/地面碰撞、落地检测 |
| `LANDING` | 检测到第一次地面撞击 | 播放 160–220ms 的落地压缩/回弹 |
| `SETTLED` | 速度低于静止阈值 | 停在脚底线，结束物理计时器；恢复浮窗 |

补充规则：

- 拖动超过阈值后松手不触发单击动作。
- 单击/双击仍沿用当前 `180ms` 延迟，避免双击先误播动作。
- 低速松手也要自然受重力；不能突然瞬移到地面。
- 最低甩出阈值从 `500 px/s` 起调；低于阈值视为轻放。
- 宠物落地后，下一次单击动作仍必须从站立开始。

### 5.3 估速与物理参数

首版以 DSH 参考实现为起点，所有参数都通过常量集中管理，并在测试中可替换：

| 参数 | 初始值 | 说明 |
| --- | ---: | --- |
| 取样窗口 | `150 ms` | 只使用最近轨迹，避免旧速度污染 |
| 最小有效跨度 | `20 ms` | 太短无法可靠估速 |
| 相邻分段最小跨度 | `8 ms` | 用于识别末段加速 |
| 端点均速权重 | `50%` | 防止只取最后一点导致抖动 |
| 分段峰值权重 | `50%` | 保留“突然甩出去”的力度 |
| 末段加速增益 | `0–60%` | 约 `8000 px/s²` 达到满增益 |
| 指数软限速 | `3600 px/s` | 防止极端甩飞 |
| 甩出死区 | `500 px/s` | 低于该值只轻放 |
| 单步最大 dt | `50 ms` | 防止卡顿后穿透 |
| 重力 | `2200 px/s²` 起步 | 通过手感测试微调 |
| 地面反弹阈值 | `40 px/s` | 低于该值直接停住 |
| 静止阈值 | `abs(vx) < 15`、`abs(vy) < 1` | 关闭物理计时器 |

实现时使用固定上限的时间步长，不做按真实卡顿时长直接积分。所有速度单位统一为 Windows 物理像素/秒；若未来支持不同 DPI 的坐标，进入物理层前完成换算。

### 5.4 碰撞与锚点

- 横向使用**可见身体 bbox**，而不是包含透明留白的整个窗口。
- 纵向使用站立帧的脚底线作为接地点，避免把透明底部留白当作地面。
- 飞行时只对整张宠物做小幅旋转/压缩，不拆分或裁切翅膀。
- 旋转建议限制在 `±8°`，以脚底附近为旋转锚点；先用极短过渡，避免像螺旋桨。
- 落地压缩底部锚定：先向下压，再 `easeOutBack` 回弹，最大过冲约 `1.08–1.12`。
- 撞墙时可以轻微反向偏移和短暂停顿，但不要把动作叠加到现有的头部动作上。

### 5.5 双屏与分界线

当前 Windows 虚拟桌面已能拿到每块显示器的 `rcWork` 工作区。物理层需要再加一个显式的显示器交接策略：

1. 每次拖动/飞行都同时计算可见身体 bbox 与当前工作区。
2. 如果目标位置的可见身体仍完整位于当前显示器，正常移动。
3. 如果只差一部分跨过分界线，不允许窗口显示“半只宠物”。
4. 进入相邻显示器后，按整窗吸附方式交接；交接位置由身体 bbox、抓取偏移和脚底线共同计算。
5. 如果两块屏幕之间有坐标空隙，宠物在边缘停住并反弹，不穿越桌面空隙。
6. 在 100/125/150% 缩放和混合 DPI 下分别测试；不以窗口中心作为唯一判断依据。

如果整窗吸附在实机上仍有明显跳变，增加 `80–120ms` 的透明度交接，而不是生成第二只宠物窗口。交接期间状态浮窗暂时隐藏，落地或交接完成后恢复。

### 5.6 状态浮窗

- 拖动时浮窗刚性跟随宠物，避免用户看不到当前任务。
- 飞行时浮窗暂时收起，避免 60 FPS 重排和屏幕边界冲突；落地后淡入恢复。
- 浮窗位置使用当前显示器工作区重新避让，不能跨分界线。
- 靠近上边缘时优先放侧面或下方；不能为了“永远在上方”把浮窗推出屏幕。
- 点击浮窗可作为打开 DSH 的快捷入口；最小化按钮保留。
- 浮窗重绘只改变尺寸/文字，不因每次窗口移动重建 Canvas 内容。

## 6. 功能路线图

### M0：基线固化（约 0.5–1 个工作日）

- 固定当前 `0.5.13` 的行为作为回归基线。
- 增加物理纯逻辑测试骨架，不改变运行中的桌宠。
- 记录当前包体积、进程内存、双屏坐标和设置持久化结果。
- 把本计划链接加入 README。

验收：现有单击、双击、右键、状态浮窗和双屏约束无变化。

### M1：物理 MVP（约 2–3 个工作日）

- 新增 `desktop/pet_physics.py`。
- 实现轨迹采样、松手估速、轻放、重力、地面/墙壁反弹、摩擦、静止休眠。
- 在 `_on_press`、`_on_drag`、`_on_release` 接入物理模型。
- 用可见身体 bbox 和脚底线修正碰撞。
- 宠物大小变化后重新计算碰撞框。
- 增加单元测试：低速死区、末段加速、限速、dt 夹取、地面反弹停止。

验收：连续甩出 20 次不穿墙；轻放不会误触发单击；松手后能自然停下。

完成情况：已实现纯物理模块、21 项单元测试、跨屏整窗交接、飞行时浮窗隐藏、
落地压缩回弹和右键安全取消。所有精灵帧统一脚底线。

`0.7.0` 补充飞行专用的 `jumping` 起飞动画，并把贴边检测从“全部姿势联合
外框”改为“当前动作外框”；宽动作开始时临时校正窗口位置，避免站立时留下
过大的展翅安全距离。回归测试增至 34 项。

`0.8.1` 将甩飞动作拆为起飞与临近地面两段：按住拖动超过点击阈值后立即播放
`jumping` 的中间帧，松手后延续起飞帧；下降接近地面时切换到 `cheer` 展翅
扇动帧，触地后立即恢复站立。这样既避开首尾仍在站立的帧，也让“拎起宠物”
这一交互有即时反馈。相关 Python 回归测试增至 45 项。

### M2：QQ 宠物式手感（约 2–3 个工作日）

- 抓取时短暂“被拎起”的身体反馈，不改变点击语义。
- 高速甩出时增加轻微滞后、整图倾斜和落地压缩。
- 撞墙提供短暂反向速度，避免无限微弹。
- 低速放下时直接受重力落地。
- 在设置中增加“甩出力度”与“减少动态效果”开关。
- 重点验证 65% 默认大小、30% 最小、180% 最大三档。

验收：甩出方向和力度可预期；落地不抖成无限弹；调大/调小后锚点不漂移。

完成情况：`0.7.0` 已实现抓取轻拉伸、甩出力度滑杆、减少动态效果开关、
更轻的重力与空气阻力、收敛后的落地压缩，以及双击后的随机伸头/歪头反馈。
设置面板拆为“通用 / 交互 / 行为”三页，并完成 `420×330` 与 `320×300`
真实窗口截图检查。

### M3：让宠物更像工作伙伴（约 2–4 个工作日）

- 任务开始：一次“抬头/注意”短动作。
- 等待审批：歪头或待机姿态，不连续点头。
- 任务成功：连续轻跳两次作为完成提醒，再回到站立。
- 任务失败：短暂低头或失败姿态，不持续循环。
- 长时间空闲：进入睡觉待机；任务开始、点击或拖动时唤醒。
- 鼠标只在宠物窗口内触发轻互动，不监听全局鼠标。
- 所有状态动作继续遵守“头部大小一致、首尾站立”的现有约束。

验收：状态动画不被工作行动画抢占；动作结束后不会残留上一姿势。

### M4：设置、恢复与稳定性（约 2–3 个工作日）

- 设置：甩出力度、减少动态效果、空闲动作频率、锁定位置、恢复默认位置。
- 增加“静默模式”：只显示状态，不自动播放待机动作。
- 增加托盘或安全的恢复入口，避免隐藏宠物后只能重新启用插件。
- 任务浮窗折叠、最小化、恢复和跨屏避让回归测试。
- 处理显示器热插拔、分辨率变化、远程桌面恢复和 DSH 重启。
- 日志只记录状态和异常，不记录用户任务正文。

验收：隐藏后可从设置或托盘恢复；显示器拔插后宠物不会永久跑到屏幕外。

已完成部分：位置锁定、恢复默认位置、空闲动作间隔（50%–200%）和设置三页
布局。托盘恢复入口仍待实现。

### M5：轻量化第一轮（约 2–3 个工作日）

- PyInstaller spec 只打包运行时需要的资源，排除 `assets/poses/_*.png`、sources 和开发截图。
- 把重复动作帧改成 atlas 或“单帧 + 时间轴”，保持现有头部尺寸和站立逻辑。
- 懒加载动作，按需解码；空闲时释放未使用帧。
- 移除死代码：当前 `client.js` 中已禁用的窗口内宠物实现、未使用的 `spritesheet.webp` 路由需先确认无兼容依赖再删。
- 记录每次构建的 tgz、EXE、assets 和运行内存。

阶段预算：

- npm tgz 从约 `23.30 MB` 先压到 `<= 21 MB`。
- `assets` 从约 `2.98 MB` 压到 `<= 1.5 MB`，不牺牲可见画质。
- 不引入新的运行时依赖。

### M6：原生轻量壳（可选但推荐，约 1–2 周原型）

只有在 M1–M4 交互稳定后启动。优先方案：

- C++17 Win32，`UpdateLayeredWindow`/`Direct2D`/WIC，或经过验证的 Rust Windows 壳。
- 复用现有状态 JSON、设置 JSON 和物理参数。
- 由 Node Host 继续负责 DSH 状态桥接，原生程序只负责窗口、渲染、输入和物理。
- 不要求用户安装 Python；不引入大型 UI 框架。

目标不是承诺固定数字，而是先做可测量原型：

- 发布包尽量控制在 `3–6 MB` 量级。
- 空闲物理计时器停止。
- 启动时间和内存均低于当前 Python 版本。
- 如果原生原型手感不如 Python 版本，继续维护 Python 版本，不为“体积”牺牲可用性。

## 7. 其他值得开发的功能

### 优先做

- **状态完成提醒**：DSH 回合正常结束时连续轻跳两次，比持续工作动画更有信息量。
- **等待审批提醒**：歪头一次或轻微呼吸，不循环点头。
- **睡觉/唤醒**：长时间无任务后休息，任务开始自动醒来；这是低成本生命感。
- **宠物窗口内抚摸反馈**：鼠标悬停 1 秒播放一次短动作，带冷却，不读全局鼠标。
- **点击浮窗打开 DSH**：减少用户寻找窗口的成本。
- **恢复入口**：托盘菜单或无冲突快捷键，解决“隐藏后找不到宠物”。
- **减少动态效果**：适合远程桌面、低性能机器和对运动敏感的用户。
- **位置锁定与恢复默认位置**：防止误拖，显示器变更后可一键复位。

### 可以后做

- Shimeji 式随机桌边漫游：默认关闭，或在静默模式外才启用。
- 在窗口顶边站立/攀爬：需要窗口枚举和更复杂的碰撞，先不要放进首版。
- 多宠物选择/主题包：先稳定单角色，避免资源和解码复杂度翻倍。
- 声音：默认关闭，且需要额外音量、静音和设备切换处理。

### 不建议做

- 喂食、等级、商店、签到、联网社交等 QQ 宠物式养成系统。它们会显著增加包体、后台网络和长期维护成本，偏离 DSH 工作伴侣定位。
- Desktop Goose 式抢焦点、改文件、遮挡桌面的“恶作剧”。
- 全局鼠标追踪或自动控制鼠标。
- 为了减小包体而压缩到明显影响宠物像素边缘和透明质量的格式。

## 8. 验收清单

### 交互回归

- [ ] 单击仍随机切换动作，第一次点击就生效。
- [ ] 双击仍只负责打开/收起 DSH，并恢复折叠浮窗。
- [ ] 右键仍只打开设置/隐藏菜单。
- [ ] 拖动超过阈值后松手不触发单击动作。
- [ ] 每个动作都从站立开始、回到站立，不残留伸头/歪头帧。
- [ ] 空闲动作间隔保持随机，且长间隔不会同时叠加多个动作。

### 物理

- [ ] 最近 150ms 估速生效，轻拖不会误甩。
- [ ] 低速度松手自然下落，不瞬间传送。
- [ ] 高速度甩出有可预测的方向和距离。
- [ ] 速度过高时被软限速，不穿出工作区。
- [ ] 地面、左右墙、天花板均不会无限微弹。
- [ ] 静止后物理计时器停止。
- [ ] 30%、65%、180% 大小下落地锚点一致。

### 双屏与状态浮窗

- [ ] 宠物可以跨到第二块屏幕。
- [ ] 跨屏过程中宠物可见身体不会被分界线切成两半。
- [ ] 状态浮窗不会跨屏，不会被推出工作区。
- [ ] 100/125/150% DPI 下位置和尺寸不漂移。
- [ ] 屏幕拔插、分辨率变化后可恢复位置。

### 包体与性能

- [ ] 构建包不包含 `_*.png`、sources 和开发截图。
- [ ] 记录 tgz、EXE、assets 和进程内存四项指标。
- [ ] 静止状态下没有高频物理定时器。
- [ ] 拖动/飞行帧率稳定，且不持续泄漏内存。
- [ ] 发布前运行 `npm pack --dry-run --json` 检查发布清单。

## 9. 风险与处理

| 风险 | 处理 |
| --- | --- |
| Tk 在 60 FPS 下抖动或 CPU 偏高 | 物理只在拖动/飞行时运行；位置取整；缓存缩放结果；必要时改用原生窗口壳 |
| 双屏混合 DPI 导致窗口尺寸变化 | 物理层统一使用工作区物理像素；实机测试 100/125/150% |
| 落地旋转破坏现有动作姿态 | 物理变换只作用于整张窗口，限制角度并优先使用压缩；动作帧逻辑不变 |
| 状态浮窗跟随造成布局抖动 | 拖动刚性跟随，飞行隐藏，落地恢复；浮窗不逐帧重建 |
| 资源 atlas 改造破坏动作首尾站立 | 先只做打包筛选和懒加载；atlas 改造单独提交并逐动作截图验证 |
| 隐藏宠物后无法找回 | 在 M4 增加托盘/设置恢复入口，不依赖重新启用插件 |
| QQ 宠物素材或代码版权 | 只借鉴交互规律，使用自己的美术和实现，不复制素材、音频或代码 |

## 10. 轻量化策略

### 立即可做

1. 从 PyInstaller `datas` 中排除开发检查图。
2. 从 npm `files` 中排除 `assets/poses/sources/*.png` 和重复帧。
3. 用动作名对应一张 atlas，或保存唯一帧并在运行时复用。
4. 按需加载动作，未使用动作不常驻内存。
5. 清理 `client.js` 中已经不挂载的窗口内宠物死代码。
6. 构建后记录包体、内存和启动时间，避免功能变多但无人察觉。

### 中期

- 对静态帧使用无损 atlas，避免每帧一整张 320x320 PNG。
- 预计算落地压缩/倾斜的少量档位，不在每一帧做 Pillow 大图变换。
- 将状态轮询、桌面渲染和动作计时器分离；静止时只留低频状态检查。
- 评估是否需要 `spritesheet.webp` 的窗口内兼容路由。

### 长期

- 原生 Win32 壳替换 Python/Tk/Pillow 运行时。
- 原生层直接读取 atlas，使用 GDI+/Direct2D 做透明窗口、旋转和缩放。
- 保持设置、状态 JSON 和物理参数兼容，实现可回退迁移。

## 11. 推荐执行顺序

1. 先完成 M1 物理 MVP，不做其他 UI 大改。
2. 用当前双屏实机验证抓取、甩出、落地和分界线。
3. 完成 M2 手感调校后，再把物理结果接到状态浮窗。
4. 状态动作和空闲睡觉放在物理稳定之后，避免多个动画系统互相抢占。
5. 最后做 M5 资源裁剪；不要在物理还未稳定时同时改 atlas 和坐标系。
6. 原生壳作为独立分支/原型验证，不直接替换稳定版本。

## 12. 默认决定

- 默认开启拖动和甩出。
- 轻放会自然下落，不要求用户一定“甩”。
- 高速甩出才触发挥动/倾斜效果。
- 飞行时收起任务浮窗，落地后恢复。
- 空闲不自动漫游，不做声音，不读取全局鼠标。
- 状态动作只播放一次，不循环点头。
- 安装包轻量化优先于增加非核心玩法。
